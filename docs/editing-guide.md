# Посібник з редагування Praxis

Усе редагування відбувається в браузері на GitHub. Встановлювати нічого не потрібно.

## Як це працює

1. Кожна стаття — це текстовий файл `.md` у папці [`src/content/articles/`](../src/content/articles/).
   - `uk/` — українські статті;
   - `en/` — англійські переклади. Переклад має **ту саму назву файлу**, що й оригінал.
2. Після кожного збереження (commit) GitHub автоматично перебудовує сайт. Через 1–2 хвилини зміни з’являються на https://marynagurak.github.io/praxis/.
3. Перебіг публікації видно на вкладці **Actions** репозиторію: зелена галочка — опубліковано, червоний хрестик — помилка (див. нижче).

## Виправити наявну статтю

1. Відкрийте файл статті, наприклад `src/content/articles/uk/pistoning-hydraulic-seal.md`.
2. Натисніть значок олівця ✏️ (Edit this file).
3. Внесіть зміни.
4. Натисніть **Commit changes…** і коротко опишіть зміну, наприклад «Виправлено термін у розділі «Аудит»».

## Додати нову статтю

1. Відкрийте [`src/content/articles/_TEMPLATE.md`](../src/content/articles/_TEMPLATE.md) і скопіюйте весь текст.
2. Перейдіть у папку `src/content/articles/uk/` → **Add file → Create new file**.
3. Назвіть файл латиницею через дефіс, наприклад `socket-interface-pressure.md`. Назва файлу стане адресою статті.
4. Вставте шаблон, заповніть поля між рядками `---` і напишіть текст статті під ними.
5. **Commit changes…**

### Поля статті

| Поле | Що вписати |
|---|---|
| `title` | Заголовок-теза |
| `description` | 1–2 речення для картки та пошуковиків |
| `category` | `news`, `research`, `biomechanics` або `discussion` |
| `section` | `upper-limb`, `lower-limb`, `orthotics`, `gait` або `textbooks` |
| `pubDate` | Дата у форматі `2026-12-01` |
| `confidence` | `high`, `moderate`, `low` або `unknown` |
| `evidenceLevel` | Рівень ієрархії доказів Praxis від 1 до 6 |
| `studyType`, `limitations` | Тип матеріалу та обмеження для блоку «Аудит доказів» |
| `terms` | Терміни UA/EN для бокової панелі |
| `question` | Питання до спільноти |
| `references` | Джерела: `text` — бібліографічний опис, `doi` — DOI без `https://doi.org/` |
| `telegram` | Посилання на пост з обговоренням |
| `featured` | `true` — велика картка на головній |
| `draft` | `true` — стаття не публікується на сайті |

> ⚠️ Репозиторій публічний: навіть чернетки з `draft: true` видно в коді. Незавершені тексти зберігайте поза репозиторієм.

### Розмітка тексту (Markdown)

```markdown
## Методологія та механіка        ← заголовок розділу (потрапляє в «Зміст»)
### Підрозділ
**жирний** і *курсив*
- пункт списку
1. нумерований пункт
> цитата
![Опис рисунка](./images/figure-1.png)
```

Зображення кладіть у папку `images/` поруч зі статтею (`src/content/articles/uk/images/`). Використовуйте лише власні ілюстрації або матеріали з відкритою ліцензією з атрибуцією. Клінічні фото — тільки за письмовою згодою пацієнта і знеособлені.

## Якщо щось пішло не так

- **Червоний хрестик на вкладці Actions.** Найчастіше причина — помилка в полях статті: зайва лапка, неправильна категорія, дата не у форматі `РРРР-ММ-ДД`. Відкрийте невдалий запуск, знайдіть рядок з назвою файлу і виправте його. Сайт тим часом показує попередню робочу версію.
- **Повернути попередню версію файлу.** Відкрийте файл → **History** → виберіть потрібну версію. Жодна зміна не втрачається назавжди.

## Технічні налаштування

- Назви розділів, підписи інтерфейсу, посилання на Telegram і дані авторки — у файлі [`src/config.ts`](../src/config.ts).
- Адреса сайту — у файлі [`astro.config.mjs`](../astro.config.mjs). Після купівлі домену її треба змінити, а в налаштуваннях репозиторію (Settings → Pages → Custom domain) вказати домен.
