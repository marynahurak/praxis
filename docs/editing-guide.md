# Посібник з редагування Praxis

Усе редагування відбувається в браузері на GitHub. Встановлювати нічого не потрібно.

## Як це працює

1. Кожна стаття — це текстовий файл `.md` у папці [`src/content/articles/`](../src/content/articles/).
   - `uk/` — українські статті;
   - `en/` — англійські переклади. Переклад має **ту саму назву файлу**, що й оригінал.
2. Після кожного збереження (commit) GitHub автоматично перебудовує сайт. Через 1–2 хвилини зміни з’являються на https://marynahurak.github.io/praxis/.
3. Перебіг публікації видно на вкладці **Actions** репозиторію: зелена галочка — опубліковано, червоний хрестик — помилка (див. нижче).

## Виправити наявну статтю

1. Відкрийте файл статті, наприклад `src/content/articles/uk/pistoning-hydraulic-seal.md`.
2. Натисніть значок олівця ✏️ (Edit this file).
3. Внесіть зміни.
4. Натисніть **Commit changes…** і коротко опишіть зміну, наприклад «Виправлено термін у розділі «Аудит»».

## Додати нову статтю

1. Відкрийте [`src/content/articles/_TEMPLATE.md`](../src/content/articles/_TEMPLATE.md) і скопіюйте весь текст.
2. Перейдіть у папку `src/content/articles/uk/` → **Add file → Create new file**.
3. Назвіть файл латиницею через дефіс, наприклад `socket-interface-pressure.md`. Назва файлу стане адресою статті.
4. Вставте шаблон, заповніть поля між рядками `---` і напишіть текст статті під ними.
5. **Commit changes…**

### Поля статті

| Поле | Що вписати |
|---|---|
| `title` | Заголовок-теза |
| `description` | 1–2 речення для картки та пошуковиків |
| `category` | `news`, `research`, `biomechanics` або `discussion` |
| `section` | `prosthetics` (протезування) або `rehabilitation` (реабілітація: фізична терапія, ерготерапія, ФРМ, психологія) |
| `pubDate` | Дата у форматі `2026-12-01` |
| `confidence` | `high`, `moderate`, `low` або `unknown` (необов’язково; без нього позначка не показується) |
| `evidenceLevel` | Рівень ієрархії доказів Praxis від 1 до 6 |
| `studyType`, `limitations` | Тип матеріалу та обмеження для блоку «Аудит доказів» |
| `terms` | Терміни UA/EN для бокової панелі |
| `question` | Питання до спільноти |
| `references` | Джерела: `text` — бібліографічний опис, `doi` — DOI без `https://doi.org/` |
| `telegram` | Посилання на пост з обговоренням, напр. `https://t.me/prosthetics_ukraine/491` |
| `featured` | `true` — велика картка на головній |
| `draft` | `true` — стаття не публікується на сайті |

> ⚠️ Репозиторій публічний: навіть чернетки з `draft: true` видно в коді. Незавершені тексти зберігайте поза репозиторієм.

### Розмітка тексту (Markdown)

```markdown
## Методологія та механіка        ← заголовок розділу (потрапляє в «Зміст»)
### Підрозділ
**жирний** і *курсив*
- пункт списку
1. нумерований пункт
> цитата
![Опис рисунка](./images/figure-1.png)
```

Зображення кладіть у папку `images/` поруч зі статтею (`src/content/articles/uk/images/`). Використовуйте лише власні ілюстрації або матеріали з відкритою ліцензією з атрибуцією. Клінічні фото — тільки за письмовою згодою пацієнта і знеособлені.

## Якщо щось пішло не так

- **Червоний хрестик на вкладці Actions.** Найчастіше причина — помилка в полях статті: зайва лапка, неправильна категорія, дата не у форматі `РРРР-ММ-ДД`. Відкрийте невдалий запуск, знайдіть рядок з назвою файлу і виправте його. Сайт тим часом показує попередню робочу версію.
- **Повернути попередню версію файлу.** Відкрийте файл → **History** → виберіть потрібну версію. Жодна зміна не втрачається назавжди.

## Технічні налаштування

- Назви розділів, підписи інтерфейсу, посилання на Telegram і дані авторки — у файлі [`src/config.ts`](../src/config.ts).
- Адреса сайту — у файлі [`astro.config.mjs`](../astro.config.mjs). Після купівлі домену її треба змінити, а в налаштуваннях репозиторію (Settings → Pages → Custom domain) вказати домен.

## Інструменти (розділ «Інструменти / Tools»)

### «Атлас локалізації міоточок та конфігурації sEMG-електродів» (версія 2)

- **Тексти** — у файлі `src/data/myomap.json`. Кожне текстове поле має дві мови: `"uk"` і `"en"`.
  - `muscles` — анатомія кожного м'яза (початок, прикріплення, іннервація, функція), обґрунтування як місця для електрода (`why`), команда для міотесту (`cmd`), перехресні наводки (`xt`), оцінка зусилля (`effort.level`: `low` / `moderate` / `high`), функціональна група (`grp`: `flex` / `ext`) і рівні, де м'яз є можливою мішенню TMR (`tmr`).
  - `levels.<рівень>.roles` — роль м'яза на цьому рівні; вона визначає колір на схемі: `primary`, `secondary`, `caution`, `conditional`, `deep` (м'язи без ролі показано як `context`).
  - `levels.<рівень>.modeNotes`, `pitfalls` — примітки рівня; `weak`, `effort`, `how`, `pitfalls`, `systems`, `references` — загальні блоки сторінки.
  - `electrodes` — палітра електродів. Розміри (`w`, `h`, мм) позначайте `"dims": true` лише тоді, коли їх підтверджено документацією виробника; інакше контур вважається схематичним.
- **Анатомія** згенерована з 3D-моделі BodyParts3D (© DBCLS, CC BY 4.0): зображення — `public/myomap/*.webp`, контури м'язів, сухожилкові зони й поперечні зрізи — `src/data/myomap-geo/*.json`. Вручну ці файли не редагуються: їх перегенеровують робочими скриптами. Атрибуцію BodyParts3D не можна прибирати зі сторінки (умова ліцензії CC BY 4.0).
- **Дві сторінки.** Довідник і методологія — `/tools/myotesting-map/` (`src/views/MyoMap.astro`); повноекранна інтерактивна мапа — `/tools/myotesting-map/atlas/` (`src/views/MyoAtlas.astro`, без шапки й підвалу сайту). Спільні тексти інтерфейсу й підготовка даних — `src/lib/myomap.ts`.
- **Поведінка** (перетягування електродів, оцінка розміщення, нижня панель на телефоні, симулятор ЕМГ) — `src/scripts/myomap-client.ts`.
- **Прев'ю мапи** на сторінці-довіднику — `public/myomap/preview-uk.webp` і `preview-en.webp` (знімки екрана мапи 1200 × 750); після помітних змін вигляду їх варто оновити.
- **Версії (MAJOR.MINOR.PATCH).** PATCH — виправлення описок і термінів без зміни логіки; MINOR — нові матеріали чи функції (електрод, рівень, примітки); MAJOR — зміна логіки вибору місць або критеріїв оцінки. Після кожної зміни оновіть `meta.version` і `meta.updated` та додайте запис на початок `changelog` у `src/data/myomap.json` — журнал і паспорт на сторінці оновляться автоматично.
- **Журнал проєктних рішень** — `docs/myomap-design-log.md` (Проблема → Варіанти → Рішення → Обґрунтування). Додавайте запис для кожного суттєвого рішення.
- **DOI і PDF-зріз (Zenodo).** Кожна версія атласу депонується в Zenodo як технічна записка (PDF українською та англійською) з власним DOI; спільний DOI запису вказує на найновішу версію. На записі Zenodo — «New version», зарезервуйте DOI, потім зберіть PDF: `MYOMAP_DOI=… scripts/myomap-snapshot/make.sh` (докладніше — `scripts/myomap-snapshot/README.md`). Після публікації додайте DOI цієї версії в `meta.doi.versions` у `src/data/myomap.json` (наприклад, `"2.2.0": "10.5281/zenodo.…"`): тоді рядок цитування й паспорт на сторінці покажуть його автоматично. Спільний DOI усіх версій — `meta.doi.concept` (10.5281/zenodo.24449468) — не змінюється.
- **Ліцензія інструмента** — `LICENSE-TOOLS.md` (зміст — CC BY-NC-ND 4.0, код — усі права захищено). Не прибирайте атрибуцію BodyParts3D.
- **Приклади систем** (`systems`) — лише з посиланням на документ виробника; перевіряйте актуальність щонайменше раз на пів року.
- **Посилання на конкретний вигляд**: `.../tools/myotesting-map/atlas/#tr_post/ed` (старі посилання без `atlas/` автоматично переадресовуються) відкриває задню проєкцію передпліччя з карткою м'яза-розгинача пальців; `#tr`, `#th`, `#ph`, `#sd` — рівні.

### «Симулятор тягової системи протеза верхньої кінцівки» (версія 2.0)

- **Сторінка** — `/tools/body-powered-simulator/` (`src/views/BodyPowered.astro`): симулятор (рівні «передпліччя» і «плече», режими пацієнта й протезиста) і технічні розділи 01–08: призначення, позначення, модель (рівняння 1–12), параметри та джерела (згруповані), верифікація і валідація, допущення та обмеження, паспорт, джерела.
- **Оформлення** — чорно-синя гама Praxis (натхнення — сайти deep-tech, без копіювання), лінійна наукова графіка без «цеглинок», позиційні позначки ([A]–[F] на задній проєкції, [1]–[5] на схемі передпліччя, [1]–[6] на рівні плеча), розмірні лінії, штамп. Описові індекси (F<sub>вх</sub>, L<sub>пов</sub>), числа, одиниці, sin і число e — прямим шрифтом, змінні — курсивом (ISO 80000-2). Символи в текстах задаються HTML-рядками з `<sub>`; англійські індекси підставляє `sym()` (таблиця `SUB_EN` у `content.ts`) — новий український індекс треба додати туди.
- **Термінальні пристрої** — `TD_DATA` у `physics.ts`: гак із пружиною (2 рівні), розщеплений гак (1–3 гумки), узагальнена кисть VO у рукавичці (медіана чотирьох кистей). Усі числа — зі стендового дослідження Smit et al. 2012 (табл. 1–2); назви виробів на сторінці не наводяться, форми на рисунках узагальнені.
- **Рівень плеча** — потрійне керування: тяга згинання ліктя (згинання плеча), передня тяга блокування (депресія + розгинання плеча; замок перемикається на кожному циклі «потягнути — відпустити»), задня тяга ТП (відведення лопаток; кут оболонки зростає на кут згинання ліктя). Числові орієнтири — Spaulding, «Transhumeral Suspension and Control» (UW Pressbooks).
- **Таблиця позначень, рівняння, перевірки** — `NOTATION`, `EQUATIONS`, `CHECKS` у `content.ts`. Перелік `CHECKS` має відповідати тестам у `scripts/tests/bodypowered.test.mjs` (11 тестів, той самий порядок).
- **Тексти, параметри, джерела, журнал змін** — `src/lib/bodypowered/content.ts` (`getUi`, `PARAM_GROUPS`, `REFS`, `CHANGELOG`, `META`). Кожен параметр має статус: `measured` (виміряно), `guide` (клінічний орієнтир) або `conditional` (умовно). Умовне значення не можна подавати як виміряне.
- **Фізика** — `src/lib/bodypowered/physics.ts` (чисті функції). Після будь-якої зміни запустіть тести: `npm test` (бенчмарки ККД 86,5 % / 74,9 % / 45,6 % і монотонність мають проходити).
- **Поведінка й малювання** — `src/scripts/bodypowered-client.ts`. Стан зберігається в посиланні (`?v=th&m=r&t=hand…`), тож посиланням можна поділитися конкретною конфігурацією.
- **Версії** — та сама схема MAJOR.MINOR.PATCH, що й в атласі: MAJOR — зміна моделі чи критеріїв оцінки (наприклад, порогів попереджень). Після зміни оновіть `META` і додайте запис на початок `CHANGELOG`.
- **Назви виробників** у симуляторі не використовуються (бренд-нейтральність Praxis): пари «трос + оболонка» описано узагальнено, зі значеннями з літератури.
